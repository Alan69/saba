# Saba — CRM & Booking Platform для автомоек Казахстана

Монорепозиторий MVP Phase 1 по ТЗ v1.4: админ-панель (шахматка, клиенты, зарплаты, дашборд, аудит), публичный виджет онлайн-записи, мультитенантный API.

## Стек

| Слой | Технология |
|---|---|
| Frontend | React 18 + Vite + Tailwind v4 + shadcn/ui (`apps/web`) |
| Backend | NestJS 10 + Prisma 5 (`apps/api`) |
| БД | PostgreSQL 16 (partial UNIQUE против двойного бронирования) |
| Кэш / брони | Redis 7 (SETNX-резервация слотов, TTL 600 сек) |
| Деплой | Docker Compose (postgres, redis, api, web/nginx) |

## Быстрый старт (Docker)

```bash
cp .env.example .env        # отредактируйте JWT_SECRET и пароль БД для прода
docker compose up --build
```

- Приложение: http://localhost:3000 (nginx проксирует `/api` → api:3001)
- API: http://localhost:3001/api/v1
- Postgres проброшен на **localhost:5433** (чтобы не конфликтовать с локальным Postgres)

Миграции применяются автоматически при старте контейнера api (`prisma migrate deploy`).

## Локальная разработка

```bash
npm install
docker compose up -d postgres redis
npm run prisma:migrate          # первая миграция / изменения схемы
npm run dev:api                 # NestJS на :3001 (нужны env из .env)
npm run dev:web                 # Vite на :3000 с proxy /api → :3001
```

Переменные для api при локальном запуске: `DATABASE_URL` (порт 5433!), `REDIS_URL`, `JWT_SECRET` — см. `.env.example`.

## Что реализовано (ТЗ v1.4, ядро Phase 1)

- **Auth**: регистрация компании → триал Business 14 дней, JWT (15 мин) + refresh-ротация (30 дней), rate limit на логин 5/мин, PIN-вход мастера (shortToken 4ч), RBAC owner/admin/master на каждом endpoint.
- **Мультитенантность**: все данные скоупятся по `company_id` из JWT на уровне приложения.
- **Визард онбординга** (7 шагов): тип бизнеса, профиль, боксы, услуги (цены по размеру S/M/L/XL), сотрудники + % зарплаты, режим работы → всё сохраняется в API, ссылка на виджет.
- **Шахматка**: сетка боксы×время, реальная текущая линия времени, навигация по датам, быстрая запись (поиск клиента по телефону / новый клиент), карточка записи.
- **FSM статусов** (ТЗ 8.5): pending → confirmed → in_progress → done → paid; отмена с обязательной причиной; `paid`/`cancelled` — финальные, переходы из них запрещены на уровне API; no_show вручную и кроном (+30 мин, каждые 15 мин).
- **Анти-фрод** (ТЗ 6.10): запрет удаления записей (только отмена), снижение цены админом ниже прайса — только с кодом владельца, лог `price_changes`, колокольчик владельцу при отмене из работы и серии отмен 3+/день.
- **Виджет записи** `/booking/:slug` (публичный): тип авто → услуга (цены по размеру) → свободные слоты из API (учёт режима работы, занятости, длительности) → бронь Redis SETNX TTL 600 → запись; при падении Redis — PostgreSQL partial UNIQUE → 409; «Powered by Saba» (Light — нельзя скрыть). Типы авто (S/M/L/XL — название + примеры моделей + вкл/выкл) настраиваются в админке (Настройки → Типы авто).
- **Клиентский портал** `/client/:slug` (публичный): вход по телефону + OTP (Phase 1 — код возвращается в ответе как dev-стаб, в проде идёт через системный WhatsApp Saba); JWT-сессия отдельным токеном (не имеет доступа к админ-API). Кабинет: приветствие + статистика, предстоящие записи с отменой (не позднее часа до визита → уведомление владельцу), история визитов, «Мои авто» (добавление/удаление), «Записаться снова».
- **Лимиты планов** (ТЗ 2.1/2.2): Light — 4 бокса/5 мастеров, Business — 8/15; 403 с текстом апгрейда; аналитика/зарплаты/NPS — только Business; триал → авто-даунгрейд в Light кроном; режим read_only при истёкшей подписке.
- **Клиенты**: база, авто (марка/номер/размер), статистика визитов и трат (обновляется при оплате), маскировка телефона для admin-роли.
- **Зарплаты**: конструктор правил (% от услуги / фикс за смену / фикс в месяц / бонус сверх порога), автоначисление % при `paid`, сводка за период.
- **Дашборд**: «Сегодня» — выручка/тренд к вчера/разбивка по способам оплаты/неявки/загрузка боксов (все планы); «Неделя» — выручка по дням, топ услуг/мастеров, спящие клиенты (Business).
- **Аудит-лог** (owner) и системные уведомления (колокольчик).
- **NPS**: оценка мастера после done (master_interface).

## Не вошло (заглушки / Phase 2)

Реальная отправка WABA/WhatsApp (OTP портала и уведомления сейчас — dev-стаб/колокольчик), CloudPayments (рекуррентная подписка, HMAC webhook), счёт-фактура PDF, импорт Excel, RFM-cron, погода, AI-поддержка, i18n RU/KZ, offline PWA, WebSocket realtime (вместо него — polling 15 сек), PostgreSQL RLS (изоляция на уровне приложения). Эндпоинты и схема БД спроектированы так, чтобы это добавлялось без миграции архитектуры.

## Смоук-тест

1. Зарегистрируйтесь на `/login` → визард → «Открыть шахматку».
2. Создайте запись через «+», проведите по статусам до «Оплачено» — у клиента вырастут визиты/траты, мастеру начислится %.
3. Откройте `/booking/<slug>` в приватном окне — запишитесь как клиент; запись появится в шахматке со статусом «Ожидание», у владельца — уведомление.
4. Попробуйте занять тот же слот дважды — второй получит 409 «Слот уже занят».
